- Agents now continue an authorized multi-step task after a status update or a completed stage; a running background command causes a wait only when the next step depends on it, and a skipped requested compaction keeps an active goal alive.
- The new `update_plan` tool stores the session's explicit items and lets the harness resume the next unblocked item when a turn ends with text only; the reminder is bounded to two turns for the same item. Plan ids are unique and stable, and at most one item may be `in_progress`.
- `goal.complete()` is now refused while the explicit plan still has `pending` or `in_progress` items; finish them or mark them `blocked` first.
- Plan items can declare a `verify` step and carry `evidence`. An item that declared a check and is marked `completed` without evidence now blocks goal completion, so "done" is backed by a recorded command and result rather than a status word. Plans without a `verify` step stay readable and are not blocked.
- Evidence is stamped with the commit it was recorded against, so a later tree reports a plan item's proof as stale instead of silently passing. The stamp is the harness's, not the model's, and staleness is advisory: it informs the operator and the continuation prompt without refusing completion on its own.
- The plan is rebuilt from the session branch's newest durable record when a worker/session rebuilds. Every model plan change is also written as a `session_plan_state` custom entry, so the plan survives a compaction that drops the `update_plan` call; sessions written before the entry keep restoring from the tool call.
- `/session` now shows the plan's settled count and up to three unfinished items, so the operator can see what still holds the task open.
- A persistent shell (`bash(..., persistent=True)`) is classified as a service: it no longer holds a goal, plan, or autonomous continuation open. Finite background jobs still do.
- A subagent's return is treated as evidence, not completion. The prompt says to read what the child changed and run the check, and the no-reply notice now carries the child's observed tool-call count: when it is zero, the notice states that the child called no tool and changed nothing, so an empty answer is not read as a finished task.
- Setting `[project] enabled = true` keeps a durable record of a session's plan and evidence outside the session. Plan updates append to the project's event log and are projected into a rebuildable SQLite read model, so the record survives the session and a lost model is restored from the log. A session that starts with no plan of its own resumes the project's stored plan in order; a session that already has one keeps it. Off by default: a session without it writes nothing.
- `/session` shows each completed plan item's recorded proof and marks a proof that was recorded against another commit, so "settled" is backed by something the operator can read.
- The whole ancestor chain of context files (`AGENTS.md` and its family) now shares one 512 KiB budget in addition to the per-file cap. Files that do not fit are named in the prompt instead of vanishing, because a model that cannot see the exclusion would act as if the tree had no instructions there.
- `jev.fallback = "llm"` is now refused when the session reads its settings, with an error that names the key and points at `jev.fallbackChain`. The prompted re-ask it asked for was never implemented, so the value previously parsed, changed nothing, and reported itself only in a log line.
- The stale-proof check now resolves the commit in the cases it used to miss: a branch whose ref `git` has packed, and a session started in a subdirectory of the repository. Both previously answered "unknown revision" and the check silently did nothing.
- The project store's plan is created once per session and reused, so enabling it no longer runs several `git` processes per session build; the recorder is invalidated when the working directory changes.
- A stored plan that broke the plan rules is repaired rather than discarded: a duplicate step id keeps its first row, a second `in_progress` step becomes `pending`, and a blank step is dropped. A plan where nothing survives is still not restored, so an empty plan cannot pass for a resumed one.
- A session's plan update no longer deletes another session's steps from the project record: a snapshot removes only the items that session wrote itself.
- Two sessions in one project keep separate plans: plan items are keyed per session, so a second session no longer takes over the first one's restored plan, and a restarted session restores the plan it wrote.
- Stopping a run now cancels a turn that is still starting: an abort that arrived between "the session is busy" and "the run is registered" used to be dropped, so the stop waited for the full model reply.
- A project read model written by another version of the build is now rebuilt from the event log instead of being refused, so upgrading no longer makes a stored plan stop resuming.
- A project record whose event log was replaced or truncated now rebuilds itself instead of freezing at the old contents.
- A project record whose last write was interrupted (a full disk) repairs that partial line before the next write, instead of becoming unreadable.
- A project record now keeps tracking removed plan steps even if its event log was briefly unreadable, instead of going silent for the rest of the session.
- Two sessions in one project can no longer fail each other when one opens the shared project record while the other writes: opening waits out a short write instead of answering "database is locked".
- The advisory tool-selection note now stops repeating itself: one rule speaks at most three times per session instead of on every matching call.
- `graph trace` and the other actions now accept a symbol named by its module path (`project_store::ProjectRecorder::sync`), not only by the full crate-qualified name or the bare leaf; a path that matched nothing used to read as "this symbol does not exist".
- Fork release artifacts are now built against the glibc 2.35 baseline the installer promises: the release pipeline builds inside the pinned Ubuntu 22.04 container, so an artifact installed on Ubuntu 22.04 starts instead of failing with `GLIBC_2.39 not found` after the installer reported the system as supported.
- Fork models can now be added or overridden in `$AGENT_DIR/models/fork-models.v1.json` (or beside `models.json`) without rebuilding the binary: the registry reads the file on every load, the compiled table is the offline fallback, and `models.json` still wins on a `(provider, id)` conflict.
- `/reload` now rebuilds a session against the settings on disk instead of requiring a daemon restart: the MCP manager reloads, the built runtime retires, and the next prompt reconstructs the tool roster and prompt from the files while the Python namespace stays revivable from its snapshot. A turn in flight is left alone and the command asks to wait.
- A daemon session's plan now survives a revive: `update_plan` writes its `session_plan_state` row through the worker's durable session file instead of the engine's in-memory manager, so the next build restores the plan.
- A malformed fork catalog now reports `Invalid fork-models.v1.json` instead of mislabeling the file as `models.json`; the built-in models still list.
- `retry.provider.timeoutMs` now bounds each daemon provider request; an unset value keeps the 300 s stall bound, and the print path keeps the default.
- Fork models are now data: the shipped `crates/pa-ai/assets/fork-models.v1.json` is the catalog the binary serves, so a new fork model is an asset edit instead of a Rust edit and a rebuild. The `$AGENT_DIR/models/fork-models.v1.json` override and `models.json` still layer on top.
- The advisory tool arbiter now covers read-only Python cells: `open`/glob/tree walks and a `subprocess` grep/find get a script-first note naming `graph.search`/`lsp.find_symbol` and the payoff (return only the values you need). Writes and deletes never get the Python note.
