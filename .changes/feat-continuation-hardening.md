- Agents now continue an authorized multi-step task after a status update or a completed stage; a running background command causes a wait only when the next step depends on it, and a skipped requested compaction keeps an active goal alive.
- The new `update_plan` tool stores the session's explicit items and lets the harness resume the next unblocked item when a turn ends with text only; the reminder is bounded to two turns for the same item. Plan ids are unique and stable, and at most one item may be `in_progress`.
- `goal.complete()` is now refused while the explicit plan still has `pending` or `in_progress` items; finish them or mark them `blocked` first.
- The plan is rebuilt from the session branch's latest `update_plan` call when a worker/session rebuilds, so the completion guard and continuation survive the rebuild.
- `/session` now shows the plan's settled count and up to three unfinished items, so the operator can see what still holds the task open.
- A persistent shell (`bash(..., persistent=True)`) is classified as a service: it no longer holds a goal, plan, or autonomous continuation open. Finite background jobs still do.
