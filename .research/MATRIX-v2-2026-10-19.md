## 3. Многопоточность: полная модель по узлам

### 3.1 Таблица исполнения

| Узел | Поток исполнения | Синхронизация | SMP/SIMD |
|---|---|---|---|
| N1 lsp | параллель (read) / sequential (rename, safe_delete, replace_body, insert) | LspManager write-guard при spawn; mux — один сервер на проект | SIMD внутри tree-sitter/grammars |
| N2 graph | фоновая задача (graph=auto) + on-demand запросы | `store: Mutex<Option<GraphStore>>` + `in_flight` CAS (single-flight) | rayon `par_iter` по файлам (SMP); blake3 SIMD внутри |
| N3 edit | **Sequential** (мутация) | `EditStore` за `Arc<Mutex<>>`; seen-lines/noop per-session | — |
| N4 jev | sequential (LLM-вызов, бюджет) | judge chain — Arc | — |
| N5 cache | вычисление в create_session (один раз) | — | — |
| N6 refine | spawn_blocking на planner | — | — |
| N7 compaction | spawn_blocking + LLM | — | — |
| N8 admission | в daemon-процессе, per-provider | circuit breaker per ProviderKey | — |

### 3.2 Кто с кем реально гоняется (проверено в коде)

- `GraphTool.ensure_indexed` ↔ фоновая задача engine: **общий флаг `in_flight`**
  (CAS) + общий SQLite файл. WAL даёт «читатели не ждут пишущего»; single-flight
  не даёт двум обходам пересечься.
- `LspManager.ensure_client` ↔ mux: write-guard через весь spawn — двойной
  старт исключён; backoff (INIT_FAILURE_BACKOFF) не ретраит упавший сервер.
- `EditHybridTool` ↔ lsp writethrough: правка применяется, затем LSP
  переоткрывает документ — порядок гарантирован Sequential-режимом edit.
- Телеметрия: никогда не в критическом пути (bounded queue, backoff, overflow
  дропает старейшие).

## 4. Решения без LLM: полный реестр (детерминированный слой)

| Решение | Файл | Механизм | LLM участвует? |
|---|---|---|---|
| Какой тул советовать | `jev/tool_arbiter.rs` | таблица правил → SuggestedTool; ростер-фильтр `has()` | нет (LLM только усиливает note при native judge) |
| Реранк хитов graph | `jev/graph_rerank.rs` | пороги + diversity в коде; judge даёт вероятности | вероятности — да; порядок — нет |
| Edit: unique-match, no-op, seen-lines | `pa-edit` | алгоритмы + thresholds | нет |
| Cache boundary, prefix stability | `prompts/system_prompt.rs` | байтовая арифметика + guard-тесты | нет |
| Truncation (AGENTS.md, skills, layers) | `truncate_context_content` | лимиты + char-boundary | нет |
| Trace честность | `pa-graph/trace.rs` | счётчик `truncated` | нет |
| Changes unindexed | `pa-graph/changes.rs` | счётчик `unindexed_files` | нет |
| Admission breaker | `pa-daemon provider_admission` | circuit per ProviderKey | нет |
| Compaction trigger | `compaction.rs` | пороги (85%), оценка | нет (LLM — только суммаризация) |
| QA-оракулы | `run_suite.py` | state/output/logs — файлы, счётчики, regex | нет (judge advisory) |
| Faux/mock provider | `pa-ai faux` | скрипт → ответы | нет (модель подменена) |
| Keyless auth (opencode) | `auth/manager.rs`, `env_api_keys.rs` | константа | нет |

**Принцип**: управление потоком — код; LLM — семантика (смысл, серые зоны,
калиброванные вероятности через jev). Даже jev — «cheap LLM», а не «без LLM»:
один вызов с типизированным ответом вместо свободного диалога.

## 5. Склейка нового и старого: 6 кейсов из нашей практики

### Кейс 1: `graph=auto` (новое) × `index` (старое)
- **Точка склейки**: `ensure_indexed` — единственная точка cold→build. Фоновая
  задача и ручной `index` пишут в один SQLite (WAL).
- **Каскад**: settings `GraphAuto` → engine `tokio::spawn` при старте → indexer
  (rayon) → SQLite → следующий `search` видит узлы. Fallback: если фон не успел —
  `ensure_indexed` строит сам (с note в ответе).
- **Кто охраняет**: `a_cold_graph_indexes_itself` (новое), `index_then_search_
  finds_the_symbol` (старое), `a_warm_graph_does_not_claim` (инвариант note).

### Кейс 2: `cache boundary` (новое) × layered prompt (старое)
- **Точка склейки**: `SystemPromptBreakdown` — старый контракт (assembled) не
  изменился; новое поле `system_prompt_cache_prefix` добавлено рядом.
- **Каскад**: resources/skills/model_prompts лимиты защищают размер префикса →
  стабильность кэша. Дата перенесена в хвост → `append_system_tests` обновлены.
- **Кто охраняет**: `cached_prefix_is_stable_across_sessions`,
  `request_prefix_is_byte_stable_across_turns`,
  `the_date_is_the_last_tail_segment_and_alone`.

### Кейс 3: `lsp` (новый) сквозь `edit` (старый)
- **Точка склейки**: `EditHybridTool` держит `Option<Arc<LspManager>>`;
  после apply — writethrough.
- **Каскад**: без writethrough → stale diagnostics → ложные code_actions.
- **Кто охраняет**: `unsupported_document_changes_write_nothing` (никаких
  частичных мутаций), `rename_refuses_to_overwrite`.

### Кейс 4: `jev` arbiter (новый) над старыми тулами
- **Точка склейки**: arbiter знает ростер (`ToolAvailability::from_tool_names`) —
  советует только присутствующее. `jev off` → arbiter off → поведение = апстрим.
- **Каскад**: новый тул F → добавить SuggestedTool-вариант + arbiter-тест + ветку
  в native_tools_section. Иначе arbiter молчит о новом тулe.

### Кейс 5: `graph=watch` (будущее) × `graph=auto` (текущее)
- **Точка склейки**: `GraphAuto::Watch` = Auto + watcher. Freshness-check
  (git-signature при каждом запросе) — первый шаг, живой watcher — второй.
- **Каскад**: watcher должен писать через тот же `ensure_indexed`-путь (single-
  flight), иначе два обхода пересекутся.

### Кейс 6: `token budget` (будущее, XERJ) × `compaction` (старое)
- **Точка склейки**: бюджет на tool-result уменьшает вход компакции → реже
  срабатывает. Инвариант: errors никогда не бюджетируются (XERJ-правило) —
  отказ, который модель не прочитает, хуже длинного ответа.

## 6. Метрики нового функционала: суть и семантическая корректность

### 6.1 Реестр источников (что уже течёт)

| Источник | Поля | Семантика |
|---|---|---|
| Session JSONL `usage` | input, output, **cacheRead**, cacheWrite, totalTokens, cost | экономика запроса |
| `logs/agent.jsonl` | phase (dispatch→prompt-built→request-sent→first-byte), phaseMs, totalMs, requestBytes | задержки по фазам |
| QA manifest | tool_calls, tool_errors, pass/task, judge verdict, log_layer | поведение на tarea |
| telemetry `admission_*` | breaker transitions, snapshot | здоровье провайдеров |
| `/admission` TUI | live breaker state | наблюдаемость |

### 6.2 Новые метрики: суть и семантика

#### A. Семантическая корректность (измеряем поведение на QA-лейне)

| Метрика | Формула | Источник | Цель | Анти-метрика |
|---|---|---|---|---|
| **Tool-choice rate** | trial'ы с ≥1 вызовом must-тула / все trial'ы | run_suite must | graph ≥80%, lsp/edit =100% | НЕ «тул упомянут в тексте» |
| **Definition-first precision@1** | correct-file-at-rank-1 на mini-benchmark | новый тест pa-graph | ≥80% (XERJ 94%) | НЕ на претрейн-коде |
| **Edit precision / scope creep** | (целевой изменён, чужие нет) / все trial | blackbox A2+A3 | 1.0 / 0.0 | НЕ по строкам диффа |
| **Stale-aware rate** | ответы с completeness-stale, сопровождённые reindex | новый (после переносa reactivegraph) | ≥90% | НЕ «0 stale» (это ложь) |
| **Semantic pass** | must ∧ must_not ∧ state | run_suite | ≥90% faux | НЕ judge в гейте |

#### B. Экономика (кэш/токены)

| Метрика | Формула | Цель |
|---|---|---|
| **Cache hit rate (session)** | ΣcacheRead / (Σinput+ΣcacheRead) | ≥90% (сейчас 90.5% общ.) |
| **Cache hit (provider)** | та же, group by provider | opencode 22% → diagnose |
| **Prefix stability** | байтовое равенство N vs N+1 | always |
| **Breakpoints used** | count(cache_control) сериализованного | 2..=4 |
| **Tool-result p95** | байты/токены | < нового потолка |
| **Cost per solved task** | Σcost / solved | тренд вниз |

#### C. Надёжность/фон

| Метрика | Цель |
|---|---|
| Auto-index p95 | <60s на repo нашего размера |
| single-flight contention | info-only |
| LSP round-trip p95 | < timeout |
| truncation events per source | alarm при >0 на типичном repo |
| fail-open regressions | 0 (mutation suite) |

### 6.3 Семантические контракты тулов (инварианты, проверяемые тестами)

| Тул | Инвариант | Тест |
|---|---|---|
| lsp.safe_delete_symbol | unavailable references → refuse, не delete | `safe_delete_refuses_when…` |
| lsp.rename_file | существующий dest → отказ; ошибка сервера → не двигать | `rename_refuses_to_overwrite…` |
| graph.trace | limit достигнут → truncated:true | `a_capped_walk_is_flagged_truncated` |
| graph.changes | не-индексированный файл → counted | `changed_files_outside_the_index…` |
| edit | reject → файл байт-идентичен | `unsupported_document_changes…` |
| graph cold | первый запрос строит И отвечает | `a_cold_graph_indexes_itself…` |

### 6.4 Правила внедрения метрик

1. **Считать на QA-лейне**, где ground truth известен; в проде — только сырьё
   (usage/timing/tool_calls).
2. **Знаменатель — тип задачи**, не время. «Доля graph-вызовов» без знаменателя
   «архитектурных вопросов» бессмысленна.
3. **Дельта против baseline**: A/B старое-vs-новое описание — иначе реврайт
   гипотеза.
4. **LLM-judge advisory-only** (qa_judge.py уже разделён: deterministic fails,
   judge в manifest).
5. **Одна метрика — одно решение.** Не влияет — не собирать.

## 7. Компрессия системного промпта (дополнение из learn_caching_2026)

Полный разбор — COMPRESSION-2026-10-19.md (16 методов с цифрами и URL). Сводка:

| Слой | Байты | ≈tok | Кэш |
|---|---|---|---|
| core.md | 14 933 | ~3 700 | prefix |
| usage.md | 6 320 | ~1 580 | prefix |
| opinionated.md | 2 385 | ~600 | prefix |
| native-tools | 5 888 | ~1 470 | tail (session-stable) |
| **Первый запрос** | **29 927** | **~7 500** | prefix 23 642 |

Ориентиры: Claude Code 27-31k первый запрос; Pi floor 1 138; Codex 1 436-5 070.
Ключевая поправка (2.8): prefix — 0.1× цена, хвост — 1.0×. Компрессия — про
качество (instruction saturation, context rot), не про деньги.

Мы в зоне пика primacy-эффекта (150-200 инструкций; у нас 31+23+126). usage.md/
opinionated.md сидят в середине prefix — худшая позиция (lost in the middle).

План (в порядке ценности):
- **C.1 Абляция 4 руки** (P1, 1-2д): полный / −usage / −opinionated / слитые ½.
  Метрики: pass rate + cache-creation + стоимость. Без этого резать — гадание.
- **C.2 Cap скиллов**: 64 → 30, описание ≤300 симв (−694 tok), убрать `<location>`
  (−2.2k симв) — итого −3-4k tok хвоста.
- **C.3 Кумулятивный бюджет context-файлов** (Codex-паттерн): сейчас лимит на файл,
  суммы нет — «5 AGENTS.md по 200 KiB» пройдут.
- **C.4 Tool-сигнатуры из core.md в схемы** (P2, 4-8ч): 113 строк ≈ 2 700 tok =
  72% core.md. Anthropic: инструкции — в description тула. После C.1.
- **C.5 usage.md: правила → суждение** (P2, после C.1): 31 мандат → принципы.
- **C.6 project-context: только готчи** (P2): AGENTS.md-исследование — контекст-
  файлы не двигают pass rate (p=1.00), но режут cache-creation и wall-clock.

Анти-паттерны: резать 80% без абляции; переносить LongLLMLingua на системный
промпт; XML-переоформление как «оптимизация»; экономить prefix ради денег.

Академическая таксономия (NAACL 2025): hard filtering (LLMLingua-семейство) и
paraphrasing — НЕ применимы к системному промпту агента (ломают точные формулировки,
Perception Compressor: хуже zero-shot). Применимы только к tool outputs и истории.
Soft prompt (Gist tokens, Shopify Sidekick 4:1, TTFT −19%, −14% GPU) — только
self-hosting с правами на веса. У кодового агента доминируют TOOL SCHEMAS (~24k из
33k у Claude Code) — сжатие промпта агента = сжатие схем/инжекций/конфигов, а не
текста инструкций. Полный разбор: COMPRESSION-2026-10-19.md §5.

## 8. Шпаргалка каскада для новой фичи F (обязательный чек-лист)

```
1. settings:  types.rs (тип+дефолт) → manager.rs (getter) → тест мержа
2. ростер:    engine.rs push + native_tool_names → СОРТИРОВКА сработает
3. промпт:    native_tools_section (WHEN TO USE в первых 200, якорь стоимости,
              honesty) → prompt_guards (токены/список)
4. кэш:       волатильное — в хвост; файлы в промпт — truncate_context_content
5. потоки:    read-only → parallel; мутация → Sequential + lock;
              фон → tokio::spawn (+spawn_blocking для CPU) + single-flight если пишет
6. арбiter:   если F в домене совета → SuggestedTool-вариант + arbiter-тест
7. метрика:   что/где/знаменатель/цель/анти-метрика (раздел 6)
8. QA:        RT если надёжность, ST если семантика выбора, blackbox NC если сценарий
9. доки:      README крейта + AGENTS.md таблица + Synthesis (трек/метрика)
```
