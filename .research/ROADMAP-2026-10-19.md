# Roadmap allspark: волны параллельной разработки

Дата: 2026-10-19. Основа: 17 исследований, 22 позиции бэклога, полный анализ
применимости (APPLICABILITY-2026-10-19.md), матрица модулей (MATRIX-v2/v3).

---

## 1. Принцип разбиения на волны

Каждая волна — набор задач, которые можно делать **параллельно без merge
конфликтов**: разные файлы, разные крейты, никаких зависимостей внутри волны.
Зависимости между волнами — явные (стрелки в графе ниже).

Оценки в часах — для одного разработчика на поток. Два потока = волна в два
раза быстрее, если связность позволяет.

## 3. Волны: задачи, связность, контракты

### Волна 1 (неделя 1-2): ~60-90ч, 4 параллельных потока

| Поток | Задачи | Крейты | Часы |
|---|---|---|---|
| 1 | A.1 описания graph/lsp (gitnexus-паттерн), A.5 honesty, A.6 definition-first буст | pa-core/prompts, pa-graph | 16-32 |
| 2 | A.2 output потолок + loop-детектор, A.9 reuse-meter тест | pa-agent, pa-ai | 8-16 |
| 3 | A.10 root-derived cache key, B.6 extract version | pa-core/auth, pa-graph | 18-28 |
| 4 | B.9 маркер обрезки с путём | pa-edit | 4-6 |

**Связность**: минимальная — каждый поток трогает разные файлы. Поток 1 —
prompts + pa-graph; поток 2 — pa-agent + pa-ai; поток 3 — auth + pa-graph;
поток 4 — pa-edit. Merge конфликтов не предвидится.

**Контракты**: никаких новых. Всё внутри существующих модулей.

**Метрики после W1**: definition-first precision@1 ≥80%; wire-тест стабильности
проходит; reuse-meter ≥90%; truncation маркер с путём.

## 4. Связность и контракты между волнами

### 4.1 Контракты, которые нельзя ломать

| Контракт | Файл | Тест |
|---|---|---|
| `Context.system_prompt_cache_prefix` тип + семантика | pa-types/ai/mod.rs | `request_prefix_is_byte_stable` |
| `ToolExecutionMode` (Sequential/Parallel) | pa-agent/types.rs | dispatch-тесты |
| `TraceResult.truncated` | pa-graph/trace.rs | `a_capped_walk_is_flagged_truncated` |
| `ChangeReport.unindexed_files` | pa-graph/changes.rs | `changed_files_outside_the_index` |
| `MAX_CONTEXT_FILE_BYTES` | pa-core/resources | `an_oversized_context_file_is_truncated` |
| `MAX_SKILLS_INVENTORY_BYTES` | pa-core/skills | `an_oversized_skills_inventory_is_capped` |
| faук provider script format | pa-ai/faux | scripted тесты |

### 4.2 Потоки данных между модулями

```
settings → engine (ростер, gates) → prompt_breakdown (cached_prefix_len)
    → Context (system_prompt + cache_prefix) → provider (Anthropic split)

Файлы → resources (truncate cap) → context_files → prompt tail
Skills → skills (inventory cap) → skills-inventory → prompt tail
Model prompts → model_prompts (cap) → prefix

graph=auto → фоновая задача → SQLite store → ensure_indexed →
    search/trace/architecture (с truncated/completeness)

edit → EditStore → writethrough → LSP переоткрывает → lsp диагностик fresh
```

## 6. Точки синхронизации между параллельными потоками

| Точка | Когда | Кто участвует | Что синхронизируем |
|---|---|---|---|
| **Конец W1** | неделя 2 | все 4 потока | merge в main, прогон полного test suite |
| **Конец W2** | неделя 3 | все 4 потока | merge + qa-tasks полный прогон |
| **Конец W3** | неделя 5 | все 4 потока | merge + integration тесты (prompt_guards, blackbox) |
| **Промпт-заморозка** | начало W3 | поток 1 (B.7) | B.7 меняет Context — другие потоки не трогают pa-types до merge |
| **LLM-judge milestone** | конец W3 | поток 1 (B.1) | judge готов → можно запускать real-model ST-задачи параллельно |

## 7. Риски параллельной разработки

| Риск | Вероятность | Митигация |
|---|---|---|
| Merge конфликты в pa-core/session_engine | высокая (3 потока) | каждый поток — свой файл; common типы — в pa-types |
| B.7 (cache boundary) блокирует B.3/B.4 | средняя | B.7 идёт первым в W3; B.3/B.4 стартуют после merge |
| LLM-judge (B.1) требует провайдера, которого нет | средняя | начать с mock-judge (faux), живой — потом |
| Расхождение метрик между потоками | низкая | общая таблица метрик в Synthesis — единый источник |
| Абляция (C.1) не даёт значимого результата | средняя | это тоже результат — значит, секция нейтральна и можно не резать |

внедрения. Первый видимый результат — через 1-2 недели (W1).
