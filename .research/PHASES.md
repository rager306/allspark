## КРИТИЧЕСКОЕ НАБЛЮДЕНИЕ: параллелизм Ф0→Ф4

**После Ф0 фазы 1, 2, 3, 4 полностью независимы** (все зависят только от Ф0):

```
                    ┌─→ Ф1 (LSP-ядро) ────────────┐
                    │                              │
Ф0 (фундамент) ─────┼─→ Ф2 (граф-диск+поиск) ──┐  │
  (1-2 дня)         │                          │  │
                    ├─→ Ф3 (closure-repair) ───┤  │
                    │                          ▼  ▼
                    └─→ Ф4 (edit-гибрид) ──→ Ф5 (клей) ──→ Ф6 (память/оптимизации)
                                                   │              │
                                                   ▼              ▼
                                              Ф7 (config) ──→ Ф8 (опции)
```

**Вывод**: 4 разработчика могут работать параллельно с первого дня после Ф0.
Без параллелизма: последовательно Ф1→Ф2→Ф3→Ф4 = 4× времени.

## Критпуть (последовательная цепочка)

```
Ф0 → Ф2 → Ф5 → Ф6 → Ф8
(фундамент → граф → клей → память/оптимизации → опции)
```
Транзитивные предшественники:
- Ф1 ← Ф0
- Ф2 ← Ф0
- Ф3 ← Ф0
- Ф4 ← Ф0
- Ф5 ← Ф0, Ф2
- Ф6 ← Ф0, Ф2, Ф3, Ф5
- Ф7 ← Ф0, Ф1, Ф5
- Ф8 ← Ф0, Ф2, Ф3, Ф5, Ф6

**MVP (80% ценности за 30%): Ф0 + Ф1 + Ф2 + Ф4 + часть Ф5 (E6/L10)**
Даёт: LSP-инструменты + граф-поиск + правки + диагностика после правки.

## Оценка времени (при N разработчиках)

| Режим | Срок | Как |
|---|---|---|
| 1 разработчик (последовательно) | ~10 фаз | Ф0→Ф1→Ф2→Ф3→Ф4→Ф5→Ф6→Ф7→Ф8→Ф9 |
| 1 разработчик (по критпути) | ~5 фаз | Ф0→Ф2→Ф5→Ф6→Ф8 (Ф1/Ф3/Ф4/Ф7 отложить) |
| 2 разработчика | ~3-4 фазы | A: Ф2→Ф5; B: Ф1→Ф4→Ф7 |
| 4 разработчика | ~2-3 фазы | A: Ф2→Ф5; B: Ф1; C: Ф3→Ф6; D: Ф4→Ф7 |

**Параллелизм внутри фаз выше, чем между** (13-40 треков) → даже один разработчик
может делать фишки фазы в любом порядке.
