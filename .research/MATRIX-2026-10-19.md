## 1. Матрица модулей: кто на что влияет

Легенда: → прямая зависимость; ⇢ влияние через состояние; ⇢⇢ каскад (A меняет B, B меняет C).

### 1.1 Слой крейтов (снизу вверх)

```
pa-types (типы, Context.system_prompt_cache_prefix)          ← всё зависит
    ↑
pa-telemetry (события)          pa-ast (tree-sitter + wasm)  pa-diff (диффы)
    ↑                                    ↑            ↑
    |                            pa-graph (SQLite граф)  pa-edit (5 режимов)
    |                                    ↑            ↑
    |                             pa-lsp (22 действия, mux, ledger)
    |                                    ↑
pa-ai (провайдеры, cache split)          |
    ↑                                    |
pa-models (каталог)                      |
    ↑                                    |
pa-agent (agent loop, ToolExecutionMode) |
    ↑                                    |
pa-core (SESSION ENGINE: тулы, промпт, settings, jev, kernel, refinement) ← ЦЕНТР
    ↑
pa-daemon (супервизор, worker'ы)
    ↑
pa-tui (рендер) ← pa-cli (композиция, print/interactive лейны)
```

### 1.2 Матрица «модуль → что затрагивает» (форк-функционал)

| Модуль/фича | Прямые связи | Каскад при изменении |
|---|---|---|
| **`lsp` (pa-lsp)** | → `pa-ast` (symbol layer), → `pa-core::tools::edit_hybrid` (writethrough), ⇢ `pa-graph` (тот же cwd) | Меняется action-набор → `prompt_guards` (core_layer_documents) + `native_tools_section` + ST-001/003 |
| **`graph` (pa-core::tools::graph + pa-graph)** | → `pa-ast`, → `pa-jev` (GraphReranker), ⇢ `pa-lsp` (тот же индекс символов), → settings (`graph.*`) | Меняется схема ответа → native_tools_section + ST-002 + arbiter (SuggestedTool::GraphSearch) |
| **`edit` (pa-edit + edit_hybrid)** | → `pa-edit` (движок), → `pa-lsp` (writethrough: правка → LSP пишет), → `skills/edit` (дублирует slice) | Меняется режим → edit_hybrid schema + skills/edit SKILL.md + ST-003 + `prompt_guards` (edit.* токены) |
| **`jev` (pa-jev + pa-core::jev)** | → `pa-graph` (rerank), ⇢ `lsp`/`edit` (arbiter советует), → pa-ai (judge chain) | Меняется action → jev/tool.rs schema + arbiter SuggestedTool + graph rerank gate |
| **`compaction`** | ⇢ `Context` (токен-бюджет), ⇢ `pa-ai` (cache split — граница считается до компакции) | Меняется стратегия → RT-010 + cached_prefix стабильность |
| **`refinement` (continual harness)** | → `pa-ai` (planner), ⇢ промпт (harness digest в хвосте) | Меняется формат → digest-парсер + RSI-цикл (harness2 F6) |
| **`prompt cache boundary`** | → `pa-types::Context`, → `pa-ai/anthropic/params`, ⇢ всё, что кладёт текст в промпт (resources/skills/model_prompts — лимиты!) | Меняется граница → `request_prefix_is_byte_stable` + `environment_is_the_last` + prompt_guards |
| **`graph=auto` (фон)** | → `pa-graph indexer` (rayon), → settings `GraphAuto`, ⇢ `ensure_indexed` (single-flight общий флаг) | Меняется политика → ST-002 (первый запрос должен отвечать) |
| **`telemetry admission`** | → pa-telemetry client (fire-and-forget), ⇢ `/admission` TUI | Меняется схема → /admission панель |

### 1.3 Критические инварианты склейки

1. **Кэш-граница** (`cached_prefix_len`): статические слои (core/usage/opinionated)
   → байтовая граница → `Context` → Anthropic split. Инвариант: сегменты до
   границы не содержат `Current date:` (тест `the_date_is_the_last_tail_segment_and_alone`).
2. **Ростер тулов** — отсортирован (`tools.sort_by(name)`) ПОСЛЕ profile-фильтра,
   ДО построения промпта. Нарушение = инвалидация кэша всех провайдеров.
3. **Action-набор ↔ промпт**: `native_tools_section_names_real_actions` + 
   `core_layer_documents_the_real_tool_surface` — дрейф ловится тестами.
4. **Writethrough**: `edit` правит файл → LSP переоткрывает документ → следующие
   `lsp` запросы видят свежий текст. Разрыв цепочки = stale diagnostics.

## 2. Многопоточность: кто где исполняется

### 2.1 Модель потоков

```
┌─────────────────────────────────────────────────────────┐
│ WORKER-ПРОЦЕСС (на сессию; daemon-супервизор следит)    │
│                                                         │
│  tokio runtime (multi-thread)                           │
│  ├─ agent loop (turn'ы, tool dispatch)                  │
│  ├─ tool calls:                                         │
│  │   ├─ ToolExecutionMode::Sequential (edit/jev: мутация)│
│  │   └─ parallel (read-only: lsp/graph reads)           │
│  ├─ фоновые задачи:                                     │
│  │   ├─ graph auto-index (tokio::spawn +                │
│  │   │   spawn_blocking → rayon par_iter по файлам)     │
│  │   ├─ mcp gating (spawn_blocking при старте)          │
│  │   └─ telemetry client (bounded queue, backoff)       │
│  └─ python kernel (отдельный процесс; RLM)              │
│                                                         │
│  SQLite: graph.db (WAL) — читатели не блокируют пишущих │
└─────────────────────────────────────────────────────────┘
```

### 2.2 Где SMP

| Место | Механизм | Масштабирование |
|---|---|---|
| **pa-graph indexer** | `rayon par_iter` по файлам (walk → parse → extract) | все ядра; 25k файлов ~минуты |
| **tool calls (read-only)** | `execute_tool_calls_parallel` (tokio JoinSet) | параллельно по числу вызовов |
| **kernel venv bootstrap** | uv (внутренне параллельный) | — |
| **compaction** | spawn_blocking (не блокирует loop) | 1 ядро (LLM-вызов) |

### 2.3 Где SIMD (сейчас нет, где осмысленно)

SIMD-контексты в коде нет. Осмысленные точки, если понадобится:
- **FTS5 tokenization** — уже в SQLite (C, векторизован самим SQLite).
- **blake3** — SIMD внутри крейта (AVX2/NEON), уже используется pa-graph для file hashes.
- Кандидат: наш `pa-diff` (word-diff) — `memchr`/`simdutf8` дали бы выигрыш на
  мегабайтных файлах. Приоритет низкий: диффы у нас по строкам, не по байтам.

Вывод: **SMP решается rayon+tokio, SIMD уже внутри зависимостей (blake3, SQLite)**.
Свой SIMD-код писать не нужно — это был бы преждевременный приоритет.

### 2.4 Правила гонок (уже закреплены)

- `GraphTool.in_flight` (CAS AtomicBool + guard-on-drop) — single-flight
  холодного старта: второй запрос не стартует второй обход.
- `edit_hybrid` store — `Arc<Mutex<EditStore>>`; seen-lines/noop живут per-session.
- LSP mux — один сервер на проект; `ensure_client` держит write-guard при spawn
  (два racing caller'а не поднимут дубликат).
- Tool dispatch — `ToolExecutionMode::Sequential` для мутирующих (edit), параллель
  только для читающих.

## 3. Решения без LLM (детерминированный слой)

Матрица «что решает код, не модель» — это наш самый ценный слой:

| Решение | Где | Чем решается |
|---|---|---|
| **Один тул вместо другого** (совет) | `jev::tool_arbiter` | детерминированная таблица (SuggestedTool::LspFindSymbol/GraphSearch/Edit) — LLM только усиливает note, если native judge |
| **Реранк search-хитов** | `jev::graph_rerank` | код: пороги + diversity; LLM — вероятности, не порядок |
| **Tool-loop детект** | `run_suite max_repeat` (QA) + `edit store noop` | счётчики и хеши, не модель |
| **Edit: unique-match, no-op, seen-lines** | `pa-edit` (fuzzy thresholds, store) | алгоритмы; sloppy — явный выбор |
| **Cache boundary** | `system_prompt_breakdown` | байтовая арифметика + guard-тесты |
| **Truncation caps** (AGENTS.md, skills, layers) | `truncate_context_content` | байтовые лимиты + char-boundary |
| **Tracing honest** | `TraceResult.truncated`, `coverage` | счётчики, не уверенность |
| **Measured gate** (XERJ-паттерн, в бэклоге) | план: `graph auto` estimate | замер, не прогноз |
| **Judge (jev ask/check/classify)** | `pa-jev` | НО это LLM-вызов — «cheap» ≠ «без LLM»; отличается от полного round-trip калибровкой и форматом |
| **QA-оракулы** | `run_suite` state/output/logs | файлы, счётчики, regex; LLM-judge advisory-only |

Принцип: **всё, что можно решить детерминированно, решается кодом; LLM — для
семантики (поиск смысла, серые зоны), не для управления потоком.**

## 4. Как новый функционал склеивается со старым (на примерах)

### Пример 1: `graph=auto` (новое) поверх `index` (старое)
- **Точка склейки**: `GraphTool::ensure_indexed` — единственная точка, где
  cold→build; фоновая задача и ручной `index` пишут в один store (WAL).
- **Каскад**: settings `GraphAuto` → engine spawn → (фоново) indexer → SQLite →
  следующий `search` видит узлы. Если фоновая задача упала — `ensure_indexed`
  восстанавливает поведение (fallback). Single-flight не даёт двум задачам
  пересечься.
- **Кто мог сломаться**: `index_then_search_finds_the_symbol` (старый тест),
  `a_cold_graph_indexes_itself` (новый), `a_warm_graph_does_not_claim` (инвариант
  «заметка только после реального build»).

### Пример 2: `cache boundary` (новое) поверх layered prompt (старое)
- **Точка склейки**: `system_prompt_breakdown` по-прежнему возвращает строку
  (`assembled`) — все старые потребители не изменились. Новое поле
  `system_prompt_cache_prefix` добавлено параллельно; провайдер без поддержки
  игнорирует его.
- **Каскад**: resources/skills/model_prompts лимиты (новое) защищают размер
  статического префикса → стабильность кэша. Дата перенесена в хвост →
  `append_system_tests` обновлены (semantic block vs technical tail).

### Пример 3: `lsp` (новый) сквозь `edit` (старый)
- **Точка склейки**: `EditHybridTool` держит `Option<Arc<LspManager>>`; после
  apply — writethrough (LSP переоткрывает документ).
- **Каскад**: правка без writethrough → stale diagnostics у lsp → ложные
  «code_actions» предложения. Тест: `unsupported_document_changes_write_nothing`
  (никаких частичных мутаций).

### Пример 4: `jev` arbiter (новый) над старыми тулами
- **Точка склейки**: arbiter знает ростер (`ToolAvailability::from_tool_names`) —
  советует только то, что реально есть в сессии. Jev off → arbiter off →
  поведение идентично апстриму.
- **Каскад**: новый тул (например, будущий `diff`) → добавить вариант
  SuggestedTool + тест arbiter + ветку в native_tools_section.

## 5. Метрики нового функционала: суть и семантическая корректность

### 5.1 Уже собирается (источники)

| Источник | Что там | Где |
|---|---|---|
| Session JSONL `usage` | input/output/**cacheRead**/cacheWrite/totalTokens + cost | каждая assistant-строка |
| `logs/agent.jsonl` (request_timing) | фазы (dispatch→prompt-built→request-sent→first-byte), phaseMs, requestBytes | per-request |
| QA manifest | tool_calls, tool_errors, pass-rate per task, judge verdict, log_layer | per-trial |
| telemetry events | admission_breaker_transition, admission_snapshot, agent started/ended | fire-and-forget |
| `/admission` TUI | live-состояние circuit breaker'ов | read-only |

### 5.2 НОВЫЕ метрики — суть и семантика

#### A. Метрики семантической корректности (главное — измеряем ПОВЕДЕНИЕ, не текст)

| Метрика | Формула | Где считается | Цель | Анти-метрика (чего не делать) |
|---|---|---|---|---|
| **Tool-choice rate** (per ST-task) | доля trial'ов с ≥1 вызовом требуемого тула | run_suite по must-правилам | graph ≥80%, lsp =100%, edit =100% | НЕ считать «упоминание тула в тексте» |
| **Definition-first precision@1** | correct-file-at-rank-1 на mini-benchmark | новый тест pa-graph | ≥80% (XERJ 94%) | НЕ мерить на коде из претрейна модели |
| **Edit precision** | изменён целевой файл / изменён хоть один не-целевой | blackbox oracle (A2+A3) | 1.0 / 0.0 | НЕ считать по diff-строкам |
| **Semantic pass** (ST) | must ∧ must_not ∧ state-oracle | run_suite (уже есть) | ≥90% на faux | НЕ блокировать по judge |
| **Retry semantic** | задача решена за ≤N запросов | logs: max_requests | ≤ бюджету | НЕ считать «быстро = хорошо» без решённости |

#### B. Метрики экономики (кэш/токены)

| Метрика | Формула | Источник | Цель |
|---|---|---|---|
| **Cache hit rate (session)** | ΣcacheRead / (Σinput+ΣcacheRead) | session JSONL usage | ≥90% (текущая 90.5%) |
| **Cache hit rate (provider)** | та же, group by provider | + model_change events | opencode 22% → диагностировать отдельно |
| **Prefix stability** | байтовое равенство префикса N и N+1 | wire-тест (уже есть) | always true |
| **Breakpoints used** | count(cache_control) в сериализованном запросе | params | ≤4, ≥2 |
| **Tool-result size p95** | байты/токены result'а | agent.jsonl | < потолка (нового) |
| **Cost per solved task** | Σcost / solved | QA manifest | тренд вниз |

#### C. Метрики надёжности/фона

| Метрика | Формула | Источник | Цель |
|---|---|---|---|
| **Auto-index latency p95** | wall-clock фоновой задачи | graph auto-index task | < 60s на repo размера our |
| **Single-flight contention** | доля запросов, пришедших во время build | AtomicBool счётчик | info-only |
| **LSP round-trip p95** | per-action latency | with_timeout бюджет | < timeout |
| **Truncation events** | счётчик по источникам (context/skills/layers) | truncate_context_content | alarm при >0 на типичном repo |
| **Fail-open regressions** | тест-инвариант (red-first) | mutation suite | 0 |

#### D. Семантическая корректность тула — контракты, проверяемые тестами

| Тул | Инвариант (семантика) | Тест |
|---|---|---|
| `lsp.safe_delete_symbol` | недоступный references → отказ, не удаление | `safe_delete_refuses_when_references_cannot_be_checked` |
| `lsp.rename_file` | существующий dest → отказ; ошибка сервера → файл не двигается | `rename_refuses_to_overwrite_*` |
| `graph.trace` | limit достигнут → `truncated:true` (capped ≠ complete) | `a_capped_walk_is_flagged_truncated` |
| `graph.changes` | не-индексированный файл → counted, не пропущен | `changed_files_outside_the_index_are_counted` |
| `edit` (reject) | отказ → файл байт-идентичен | `unsupported_document_changes_write_nothing` |
| `graph` cold | первый запрос строит и ОТВЕЧАЕТ (не «0 hits») | `a_cold_graph_indexes_itself_on_the_first_query` |

### 5.3 Как встраивать метрику (контракт)

1. **Считать в оракулах/тестах, не в проде** — семантика измеряется на QA-лейне,
   где ground truth известен. В проде — только сырье (usage, timing, tool_calls).
2. **Знаменатель фиксировать.** «Доля вызовов graph» без знаменателя «архитектурных
   вопросов» бессмысленна. Знаменатель = тип задачи (ST-002), не время.
3. **Дельта против baseline.** A/B старое-описание vs новое на ST-002 — иначе
   реврайт остаётся гипотезой (learn_tool_descriptions, §8).
4. **Никаких LLM-оценок в блокирующем гейте** — judge advisory-only (qa_judge.py
   уже так разделён: deterministic fails, judge lands in manifest).
5. **Одна метрика — одно решение.** Если метрика ни на что не влияет — не собирать.

## 6. Мини-карта каскада для БУДУЩИХ фич (шпаргалка)

Добавляешь новую фичу F → проверь по списку:

1. **Settings**: тип в `types.rs` + getter в `manager.rs` + тест мержа.
2. **Ростер/тул**: регистрация в `engine.rs` (push + native_tool_names) →
   СОРТИРОВКА сработает сама → `native_tools_section` (описание с WHEN TO USE) →
   `prompt_guards` (токены в core.md или в списке допущенных).
3. **Кэш**: не класть волатильное в prefix; если F пишет в промпт файлы — лимит
   `truncate_context_content`.
4. **Параллель**: read-only → можно в parallel; мутация → Sequential + lock.
   Фон → `tokio::spawn` + `spawn_blocking` для CPU; single-flight если пишущий.
5. **Метрика**: что считаем, где (QA-лейн или прод), знаменатель, цель, анти-метрика.
6. **QA**: RT-задача если надёжность, ST-задача если семантика выбора, blackbox
   negative controls если пользовательский сценарий.
7. **Документация**: README крейта + AGENTS.md таблица + Synthesis (трек/метрика).
